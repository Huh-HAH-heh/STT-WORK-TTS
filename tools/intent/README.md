# Local Windows Intent and Generation Engines

Vosk только переводит речь в текст. Однозначные сценарии обрабатывает C# parser, свободные команды — компактная Qwen3-0.6B. Qwen3-4B запускается по требованию: для сложного intent fallback, кратких ответов и генерации длинных текстов.

## Компактная модель команд

- Qwen3-0.6B Q4_K_M (QuantFactory GGUF conversion), около 484 MB.
- Порт 8083, alias stt-fast-intent, контекст 2048.
- Установщик проверяет SHA-256; файл модели не хранится в Git.

## Большая модель

- Qwen3-4B-Instruct-2507, GGUF Q4_K_M, около 2.5 GB, Apache 2.0.
- Порт 8082, alias stt-intent.
- Используется для fallback сложных команд, ответов на вопросы и генерации текстов. Сервер запускается C# по первому запросу.

Модель не входит в Git и portable ZIP. Она скачивается отдельно и проверяется по SHA-256.

## Установка модели

Из корня репозитория:

~~~powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\intent\Install-QwenIntentModel.ps1
~~~

Модель появится в папке models/intent. Установщик использует curl.exe, скачивает файл с поддержкой Range/resume, повторяет неудачные попытки и проверяет SHA-256 по закреплённой ревизии Hugging Face.

Если подключение оборвалось, не удаляй файл с расширением .download. Просто повтори ту же команду установки: загрузчик продолжит с сохранённого места.

## Автоматический запуск вместе с приложением

Рекомендуемый способ — запускать из корня репозитория:

~~~cmd
Start.cmd
~~~

Стартовый сценарий проверит SHA-256 Qwen, наличие Vosk и Python-окружение выбранного TTS. Если llama-server на настроенном порту не отвечает, скрипт найдёт установленный `llama-server.exe` и поднимет сервер в фоне. Ручной запуск ниже нужен только для самостоятельной диагностики.

## Запуск сервера

Нужен Windows build llama-server.exe с Vulkan или CPU backend. Если llama-server.exe добавлен в PATH:

~~~powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\intent\Start-IntentModel.ps1
~~~

Либо передай полный путь к серверу:

~~~powershell
.\tools\intent\Start-IntentModel.ps1 -ServerPath "C:\llama.cpp\build\bin\Release\llama-server.exe"
~~~

Сервер слушает только 127.0.0.1:8082; наружу в локальную сеть он не выставляется. Алиас модели — stt-intent.

Если на GPU уже загружена большая модель (например, Qwen3-Coder 30B), освободи VRAM перед запуском 4B-модели либо запусти intent-модель с параметром -GpuLayers 0 для CPU. Не стоит одновременно загружать обе модели в 8 GB VRAM без проверки фактического распределения памяти.

## Роли моделей и запуск

`Start.cmd` устанавливает компактную Qwen3-0.6B и запускает её сервер на порту 8083. Веса Qwen3-4B устанавливаются отдельно, но её сервер на порту 8082 остаётся выключенным до первого fallback/вопроса/генерации.

Ручной запуск быстрой модели: `tools\\intent\\Start-FastIntentModel.ps1`.
Ручной запуск большой модели: `tools\\intent\\Start-IntentModel.ps1`.

Запросы на написание письма/статьи/доклада сохраняются в `data/generated` и открываются в Блокноте. Короткие вопросы озвучиваются ответом Qwen 4B.

## Проверка понимания без микрофона

Когда сервер запущен:

~~~powershell
dotnet run --project .\src\STT.WorkTTS\STT.WorkTTS.csproj -c Release -- --intent-demo
~~~

Примеры фраз:

- Который час?
- Поставь таймер на пять минут.
- Открой блокнот.
- Сделай громкость на двадцать процентов ниже.
- Покажи рабочий стол.
- Открой настройки Windows.

После этого запускай приложение обычным способом. Vosk превращает речь в текст; C# parser или Qwen3-0.6B разбирает команду. Qwen3-4B подключается только при сложном разборе, вопросе или генерации текста.

## Разрешённые команды первой версии

- system.get_time, system.get_date, system.get_datetime
- timer.start, timer.cancel
- app.open — блокнот, калькулятор, проводник, браузер, настройки
- url.open — только HTTP/HTTPS
- window.show_desktop
- audio.set_volume, audio.adjust_volume, audio.mute, audio.unmute
- system.lock

Операции с файлами, PowerShell/CMD, реестром, выключением компьютера и другими потенциально опасными действиями не исполняются. Для них нужна отдельная система подтверждений.

Таймеры работают, пока приложение STT Work TTS запущено. Перезапуск приложения сбрасывает активные таймеры. Постоянные напоминания и Windows Task Scheduler — отдельный следующий этап.

## Архитектура безопасности

LLM возвращает JSON по ограниченной схеме. C# повторно проверяет action и параметры, затем вызывает только конкретные методы Windows. Модель не генерирует исполняемые PowerShell/CMD-команды, shell-код или произвольные пути запуска.

## Проверка микрофона и STT

Чтобы использовать микрофон, Vosk и нейросетевое понимание без зависимости от установленного TTS-голоса:

~~~powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\Install-VoskModel.ps1
Start.cmd --stt-demo
~~~

Этот режим записывает звук с микрофона, распознаёт его Vosk, отправляет текст в Qwen и выполняет разрешённое действие. Ответ печатается в консоль; синтез речи отключён только на время теста. Обычный запуск без `--stt-demo` включает настроенный TTS.

## Голосовой вывод

Основной TTS в приложении — Silero v5.6 / xenia. Запасной вариант — xVibePocketTTS / female_silky. После установки зависимостей выбери движок при запуске:

~~~powershell
.\\Start.cmd --tts silero --voice xenia
.\\Start.cmd --tts xvibe --voice female_silky
~~~

Можно выбрать другой голос движка через `--voice`. Полный список: `.\\Start.cmd --list-voices`. Без параметров используется Silero / xenia. При первом запуске Silero может скачивать веса до 20 минут; выводится прогресс с префиксом `[TTS]`. После этого модель остаётся в памяти между репликами.
