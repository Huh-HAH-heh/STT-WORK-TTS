# STT Work TTS — C# edition

Компактный локальный голосовой помощник для Windows x64. Основное приложение и маршрутизация команд реализованы на C# / .NET 10; Python используется только в отдельных долгоживущих адаптерах выбранных TTS-моделей.

## Конвейер

Микрофон → Vosk STT → быстрый парсер / Qwen3-0.6B → C# Intent Router → Windows API → TTS. Qwen3-4B запускается по требованию для сложных запросов и генерации текста.

- Захват микрофона и воспроизведение сделаны через NAudio.
- Русское офлайн-распознавание выполняет Vosk .NET.
- Однозначные сценарии обрабатывает детерминированный C# parser; свободные формулировки разбирает Qwen3-0.6B Q4_K_M через отдельный локальный llama-server.
- Неоднозначные и сложные команды могут перейти на Qwen3-4B. Большая модель отвечает на вопросы и генерирует длинные тексты; её сервер запускается только при первом таком запросе.
- Генерация длинного текста идёт параллельно с независимыми Windows-действиями, сохраняет результат в data/generated и открывает его в Блокноте.
- Windows-действия маршрутизируются через каталог типизированных действий: Win32 API, Core Audio и отдельные консольные адаптеры.
- Qwen возвращает структурированный план, а не исполняемую командную строку. Явный запрос «выполни в CMD ...» перехватывает детерминированный парсер и сохраняет команду дословно.
- CMD-адаптер разрешает только отдельные диагностические команды из списка; PowerShell, скрипты, цепочки команд и перенаправление отключены. Перед любой буквальной CMD-командой запрашивается подтверждение.
- Блокировка ПК и закрытие процессов требуют подтверждения. Закрытие приложения начинается со штатного CloseMainWindow; принудительное завершение не происходит автоматически.
- Для taskkill обязателен конкретный PID; завершение по имени процесса запрещено. Перед запуском повторно проверяются PID, имя и время старта процесса; системные процессы защищены от завершения.
- Таймеры, дата и время исполняются детерминированным кодом C#, а не вычисляются нейросетью.
- Основной TTS — Silero v5.6, голос xenia. Запасной движок — xVibePocketTTS, голос female_silky.
- Модели Silero и xVibe загружаются отдельными Python worker-процессами один раз и остаются в памяти, пока работает приложение. Захват микрофона, команды, WinAPI и воспроизведение WAV остаются в C#.
- Piper и Windows SAPI сохранены как дополнительные legacy-варианты, но больше не являются значением по умолчанию.
- Записи, заметки и речь не сохраняются на диск без включения соответствующих параметров.

## Голосовое управление Windows

Примеры поддерживаемых команд:

~~~text
покажи активные процессы
закрой процесс номер три
закрой Discord
заблокируй компьютер
выполни в CMD tasklist /fo csv
выполни в CMD ipconfig /all
выполни в CMD taskkill /PID 1234 /F
~~~

Команда «покажи активные процессы» выводит нумерованный список до 30 процессов: сначала приложения с окнами, затем остальные по использованию памяти. Номер действует 2 минуты и относится только к последнему показанному списку. Для работы с процессом говори «закрой процесс номер три» или «заверши процесс номер 3». Перед закрытием помощник называет выбранное приложение и PID и просит «подтверждаю» или «отмена». Индекс не является PID и не может выбрать процесс вне сохранённого списка.

Для закрытия приложения по имени, блокировки компьютера и каждой буквальной CMD-команды приложение сначала показывает цель/команду и просит «подтверждаю» или «отмена». Подтверждение действует 30 секунд и относится только к одному ожидающему действию. Новая команда сбрасывает старый запрос.

Буквальный CMD-режим принимает только одну команду за раз. Сейчас разрешены диагностические утилиты и работа со списком процессов: `tasklist`, `taskkill` по PID, `ipconfig`, `whoami`, `systeminfo`, `ping`, `tracert`, `nslookup`, `where`, `dir`, `type`, `hostname`, `getmac`, `netstat`, `driverquery`, `ver`, `cd` и `echo`. Командные цепочки, перенаправление, PowerShell и скрипты не поддерживаются.

## Запуск готового архива

1. Открой вкладку Actions репозитория.
2. Скачай STT-WORK-TTS-Windows-x64 из последнего успешного запуска workflow.
3. Распакуй ZIP в отдельную папку.
4. Запусти Start.cmd.

В portable-архиве есть стартовый bootstrap. На целевом Windows x64 ПК нужен Python 3.12 x64 для Silero/xVibe, а также llama-server.exe (в PATH или в стандартном каталоге Docker Desktop inference). При первом запуске Start.cmd проверяет и устанавливает модели и Python-окружение, затем запускает llama-server в фоне. Облачные API не используются; GPU для Qwen опционален, доступен CPU-режим.

## Сборка разработчиком

Нужен .NET 10 SDK и Windows x64. При первой сборке скрипт загрузит модель Vosk, нативный Piper CLI и один голос.

~~~powershell
git clone -b feature/windows-voice-intents --single-branch https://github.com/Huh-HAH-heh/STT-WORK-TTS.git
cd STT-WORK-TTS
.\RUN.cmd
~~~

Или вручную:

~~~powershell
powershell -ExecutionPolicy Bypass -File .\build_portable.ps1
~~~

Готовый архив появится в корне репозитория: STT-WORK-TTS-Windows-x64.zip.

## Автоматическая проверка и запуск

Для запуска используй:

~~~cmd
Start.cmd
~~~

Стартовый сценарий проверяет необходимые компоненты и при необходимости подготавливает их:

- проверяет Vosk и загружает русскую STT-модель, если её нет;
- проверяет GGUF Qwen3-0.6B и скачивает её при отсутствии;
- запускает быстрый intent-server на 127.0.0.1:8083;
- не загружает Qwen3-4B при обычном старте; при первом сложном запросе или генерации скачивает её (около 2.5 GB) и поднимает сервер на 127.0.0.1:8082;
- проверяет Python-окружение выбранного TTS и устанавливает зависимости при необходимости;
- запускает приложение после успешной проверки.

Первый старт загружает компактную модель Qwen3-0.6B (~484 MB) и необходимые зависимости. Большая Qwen3-4B (~2.5 GB) загружается отдельно только при первом запросе, которому она действительно нужна. Если сервер Qwen не найден, сценарий ищет его в PATH и в `%USERPROFILE%\\.docker\\bin\\inference\\llama-server.exe`. Логи фонового сервера сохраняются в `data\\logs`.

Проверка микрофона без озвучивания:

~~~cmd
Start.cmd --stt-demo
~~~

Проверка только понимания текстовых команд:

~~~cmd
Start.cmd --intent-demo
~~~

## Выбор TTS при запуске

По умолчанию запускается **Silero / xenia**. Выбор движка и голоса делается параметрами команды — редактировать appsettings.json не нужно.

Список поддерживаемых голосов:

~~~powershell
.\\Start.cmd --list-voices
~~~

Основной движок:

~~~powershell
.\\Start.cmd
.\\Start.cmd --tts silero --voice xenia
.\\Start.cmd --tts silero --voice kseniya
.\\Start.cmd --tts silero --voice eugene
.\\Start.cmd --tts silero --voice aidar
.\\Start.cmd --tts silero --voice baya
~~~

Запасной xVibePocketTTS:

~~~powershell
.\\Start.cmd --tts xvibe --voice female_silky
.\\Start.cmd --tts xvibe --voice male_deep
.\\Start.cmd --tts xvibe --voice male_authoritative
~~~

Если при запуске указать только `--tts xvibe`, автоматически выберется `female_silky`. Если указать только `--tts silero`, выберется `xenia`.

При запуске Start.cmd выбранный runtime проверяется и устанавливается автоматически, если его нет. Для ручной установки можно вызвать Install-TtsLab.ps1 с параметром -Engine silero или -Engine xvibe.

Python-окружения хранятся в tools/tts-lab и не включаются в Git. При первом старте Silero может скачать репозиторий и веса модели; на это отведено до 20 минут. Во время загрузки показываются сообщения `[TTS]`. После успешной загрузки модель остаётся в памяти до завершения приложения и повторно скачиваться не должна.

Режим проверки микрофона и STT отключает TTS и не требует Python-окружения:

~~~powershell
.\\Start.cmd --stt-demo
~~~

## Лаборатория сравнения голосов

Для повторного прослушивания вариантов используй [TTS Lab](tools/tts-lab/README.md). Она генерирует одинаковую фразу для разных движков, проигрывает результаты и сохраняет оценки в CSV. Python используется только для изолированных TTS worker-процессов; микрофон, Vosk, обработчик команд, Windows API и аудиопроигрывание остаются в основном C#-приложении.

## Лицензии

См. THIRD_PARTY_NOTICES.md. У Silero, xVibePocketTTS, их весов и ресурсов голоса разные условия распространения; перед распространением собранного приложения проверь актуальные лицензии моделей и runtime.
